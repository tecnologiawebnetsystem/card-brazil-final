# Contribuição

1. Identifique o domínio afetado antes de editar arquivos.
2. Prefira criar ou alterar um caso de uso em `back-end/domains/<dominio>` em vez de colocar regra na página.
3. Use componentes existentes de `components/ui` e tokens do design system.
4. Valide com TypeScript, lint e `git diff --check`.
5. Para mudanças visuais, valide a rota no navegador.
6. Atualize a documentação quando mudar arquitetura, banco ou contrato de API.
7. Use commits pequenos e descritivos por domínio ou camada.
